# How Three AI Coding Agents Manage Context: A Beginner's Claude Code × Codex × Cursor Comparison

**The value in one line**: Context management isn't a private trick belonging to any one tool. It's a craft that every coding agent shares. Once you see how Claude Code, OpenAI Codex, and Cursor each solve the *same* problem — a context window that is *finite and degrades as it fills* — switching tools no longer means relearning from scratch.

**Who this is for**: AI builders who use Claude Code / Cursor / the API and can run a script, but aren't systems engineers. You don't need to read harness source code — you just need to know, on every turn, what to *keep, drop, and isolate*. The deep end (7-layer memory architectures, source-level internals) gets one-line asides plus links; a skim reader can stop at the end of any section.

> **This piece's working thesis (an editorial stance, not an author-signed take)**: There are already plenty of "Claude Code context management" tutorials, and almost all of them lock onto a single tool. The transferable insight is that three tools solve *one* structural problem with different mechanisms. See through that layer, and most of the cost of switching tools collapses.

---

## 1. The one fact to internalize first: context is finite, and it rots

**Definition**: A context window is every token a model can "see" in a single inference pass — the system prompt, the conversation history, every tool call and its output, and any files you had it read. **Context management is the act of deciding, inside that finite and steadily-degrading window, what to keep, what to drop, and what to isolate.**

Accept two hard facts up front, and every operation later stops being rote memorization:

**Fact 1: Context is a finite resource with diminishing returns — bigger is not better.** Anthropic's engineering blog calls it the model's **attention budget**: every extra token spends that budget rather than adding to it for free (source: [Anthropic, *Effective context engineering for AI agents*, 2025-09-29](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)). The reason is baked into the transformer: tokens relate to one another pairwise, so the cost grows roughly with n², and the longer the window, the thinner the attention each token receives.

**Fact 2: The degradation is empirical, not folklore.** A Chroma study tested **18 leading models** (including GPT-4.1, Claude 4, Gemini 2.5, and Qwen3) and found the same thing across all of them: **longer input, worse performance — even on trivially simple tasks**. More counterintuitively, the decline starts well before the window is full, and a single irrelevant distractor does *more* damage as the context grows longer (source: [Chroma, *Context Rot*, 2025-07-14](https://www.trychroma.com/research/context-rot)).

Put the two together and you get a sentence worth taping to your monitor: **your goal is signal-to-noise, not fullness.** A 1M-token window doesn't free you from managing context — it buys you more time to intervene *before* the model gets dumb.

## 2. One problem: every tool has to answer keep / drop / isolate

Once you accept "finite and rots," every coding agent is forced to answer the same three questions. Those questions *are* your mental map for reading any tool:

- **Keep what?** — Which history is worth preserving, and how do you carry it without blowing the window?
- **Drop what?** — Which intermediate steps, failed attempts, and junk tool output should you actively clear?
- **Isolate what?** — Which work can run in a *separate* window, returning only the conclusion?

The table below is this article's skeleton. Three columns for three tools; beyond the visible rows there's an "invisible sixth move" that Section 5 covers on its own:

| Dimension | Claude Code | OpenAI Codex | Cursor |
|-----------|-------------|--------------|--------|
| Compaction (condensing what to keep) | `/compact` (lossy, steerable) + 7-layer auto micro-compaction | Auto-compacts past a threshold, returns a compaction item carrying `encrypted_content` | Runs until the window fills and there's no room left to respond |
| Clear / restart (what to drop) | `/clear` (you write the brief, precise restart) | Open a new thread | Open a new chat |
| Rewind (drop a failed attempt) | `/rewind` (`esc esc`) | — | — |
| Isolation | subagent in its own context window | No equivalent primitive captured this pass | Skills load dynamically vs Rules stay resident |
| Cache discipline (the invisible sixth move) | Keep the prompt-cache prefix stable | Don't edit `AGENTS.md` mid-session — it invalidates the system-prompt cache | `.cursor/rules/*.mdc` with `alwaysApply:true` stays resident and burns tokens |

## 3. Compaction: how three tools crush a long history into a short state

**Conclusion first**: compaction is the automation of "keep what" — when the history gets too long, the tool condenses it into a shorter state so the window can keep working. The difference between the three is *what form* they condense into.

**Claude Code** gives you two manual switches plus an automatic backstop:
- `/compact` lets the model decide what matters (lossy), but you can steer it: `/compact focus on the auth changes, drop the test debugging`.
- Underneath sits automatic micro-compaction that clears old tool results before each turn and reduces large file reads to a preview (source: [Troy Hua's reverse-engineering of the Claude Code harness, 2026-04-01](https://x.com/troyhua/status/2039052328070734102)).

**OpenAI Codex** has one difference worth memorizing as a beginner: past a threshold it auto-compacts, and what it returns isn't a block of *summary text* but a compaction item carrying an opaque **`encrypted_content`** — it preserves the model's latent understanding rather than a human-readable summary (source: [OpenAI, *Unrolling the Codex agent loop*, 2026-01-23](https://openai.com/index/unrolling-the-codex-agent-loop/); see also the official write-up of the Codex execution cycle, [Run long-horizon tasks with Codex](https://developers.openai.com/blog/run-long-horizon-tasks-with-codex)). By contrast, Claude's `/compact` "summarizes into text" while Codex "preserves a latent state" — same move, two philosophies.

**Cursor** puts it more plainly in its public docs: when the conversation gets too long, the window fills until there's no room left to respond (source: [Cursor Docs](https://cursor.com/docs)). It leans more on you starting a fresh chat than on an explicit compaction command.

Action item for beginners: **don't wait for the automatic trigger.** Compact proactively while the context is still healthy and the model still sharp — and add a direction — because a model is at its worst at judging what to keep exactly when the window is fullest.

## 4. Isolation (subagent / Skills): keep the mess out of the main window

This is the section people most often misread, so let's nail the conclusion first: **the core value of a subagent is context isolation, not parallelism.**

Many assume spawning a child agent is about "doing several things at once." The real value is elsewhere — any work that doesn't need the *main* agent's own reasoning (bulk mechanical operations, scoped research, parallelizable exploration) gets handed to a **separate window**, which returns only the conclusion. All that intermediate tool output, trial-and-error, and noise stays *out* of the main window (source: [Boris Cherny, creator of Claude Code, on hidden features and subagent usage](https://x.com/bcherny/status/2038454336355999749)).

A reflex you can apply on the spot: **"After this step, do I still need the tool output itself, or only the conclusion?"** Only the conclusion → hand it to a subagent.

The parallels across tools:
- **Claude Code**: named subagents (e.g. `code-simplifier`, `verify-app`), each running in its own context window.
- **Cursor**: Skills **load dynamically** vs Rules **stay resident** — Skills enter the window only when needed, a "use it and leave" flavor of isolation; this is the cross-tool parallel to Claude's *just-in-time retrieval* (source: [Cursor Agent Best Practices](https://cursor.com/blog/agent-best-practices)).
- **Codex**: this research pass didn't capture a first-party primitive equivalent to subagents, so no hard claim here.

If you want clean vocabulary for this, Simon Willison's three-way split is handy: **context quarantine / pruning / summarization** (source: [Simon Willison's context-engineering tag](https://simonwillison.net/tags/context-engineering/)).

## 5. The invisible sixth move: protect the prompt cache (a ~200x cost gap)

The first five moves all govern *what goes in the window*. There's one more that lives outside the window yet directly sets your bill — **protecting the prompt cache.**

**Definition + number**: major APIs cache the prompt prefix server-side (roughly a 1-hour TTL). At a 200K-token context, a **cache hit costs about \$0.003 and a cache miss about \$0.60 — a ~200x difference** (source: [Thariq, *Lessons from building Claude Code: prompt caching is everything*, 2026-04-30](https://claude.com/blog/lessons-from-building-claude-code-prompt-caching-is-everything)). Anthropic treats cache hit rate as an SLO internally — when it drops, they file a SEV. That's how load-bearing this is.

The catch: **a cache hit requires the prefix to be byte-for-byte identical.** Edit a system-level file mid-session and the prefix changes, the whole cache is void, and the next request is priced as a miss. So one discipline projects onto three tools as three sentences:

- **Claude Code**: the system goes to great lengths to keep the API prefix byte-stable — even subagents inherit the parent's full prefix to preserve the hit (source: Troy Hua's reverse-engineering, above).
- **OpenAI Codex**: the official guidance is explicit — **don't edit `AGENTS.md` mid-session**, it invalidates the system-prompt prefix cache (source: [OpenAI, *Unrolling the Codex agent loop*](https://openai.com/index/unrolling-the-codex-agent-loop/)).
- **Cursor**: rules with `alwaysApply:true` in `.cursor/rules/*.mdc` stay resident on every request — resident both burns tokens and means touching them moves the prefix (source: [Cursor Docs](https://cursor.com/docs)).

Action item: **don't edit `CLAUDE.md` / `AGENTS.md` / Rules mid-session.** If you must, edit, then start a fresh session. This move doesn't change output quality — only your bill. By a factor of 200.

## 6. The five per-turn options for Claude Code users

If Claude Code is your main driver, all the theory above lands on one concrete muscle memory: **every time Claude finishes a reply, you're at a branch point with five options — and most people only ever use the first.**

| Option | When to use it |
|--------|----------------|
| **continue** | Keep going; the most-used and most-overused |
| **rewind (`esc esc`)** | The last attempt failed — roll back to before it and re-prompt, rather than leaving the failure in-window and "correcting" |
| **`/compact`** | Finished a task, or the window is ~half full — compact proactively (with direction) |
| **`/clear`** | Switching to unrelated work — write a brief, wipe, restart on a clean prefix |
| **subagent** | You don't want this step's intermediate output, only its conclusion |

The single habit that best signals context-management skill is **rewind**: instead of telling the model "that didn't work, try X" (which leaves the failed attempt polluting everything after), roll back to before the failure and re-prompt carrying the lesson (source: [Thariq, *Using Claude Code: Session Management & 1M Context*, 2026-04-16](https://x.com/trq212/status/2044548257058328723)).

## 7. Closing: switch tools without relearning

Put the three tools back into one table and the thesis proves itself — these aren't three separate sets of tricks to memorize, but **three dialects of one craft**:

| What you want to do | Claude Code | Codex | Cursor |
|---------------------|-------------|-------|--------|
| Condense long history | `/compact` + auto micro-compaction | auto-compact (`encrypted_content`) | new chat |
| Drop a failed attempt | `/rewind` | new thread | new chat |
| Isolate the mess | subagent | — | Skills load dynamically |
| Save money (guard cache) | keep prefix stable | don't edit `AGENTS.md` | go easy on resident Rules |

See through that table and what you carry across is **judgment**, not shortcuts. Shortcuts change with the tool; judgment — *"should this step be kept, dropped, or isolated?"* — is common to all three.
