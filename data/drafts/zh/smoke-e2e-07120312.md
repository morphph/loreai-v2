# AI 写的代码，为什么不能只让 AI 自己审？

今年，Anthropic 说自家每个工程师的代码产出涨了 **+200%**（[Boris Cherny 官方自述](https://x.com/bcherny/status/2031089411820228645)）。Claude Code 的创造者本人连续两个月 100% 用 AI 写代码、零手改、日均 20 多个 PR。写代码这件事，正在以肉眼可见的速度变便宜。

于是瓶颈换了个位置：不再是「谁来把代码敲出来」，而是「谁来审这堆代码」。Anthropic 的回应是给每个 PR 派**一队 agent** 并行找 bug、再加一个验证步骤过滤误报，官方口径是「工程师标记为错误的发现 <1%」（[Anthropic Code Review 公告](https://claude.com/blog/code-review)）。Cursor 的 BugBot 每月处理 200 万个 PR，把 `/review` 前移成 push 前的闸门（[Cursor BugBot](https://cursor.com/bugbot)）。「派一队 AI 审每个 PR」，正在变成 2026 年的默认动作。

**但这里有个偷换：如果写代码的和审代码的是同一类 AI，那到底有没有人真的理解过这段代码？**

这就是本文的立场（take）:AI 结对时代，写代码已经变便宜，真正的护城河是「有没有人真的重建过这段代码的意图」。而**单模型闭环自审**——AI 写、同一类 AI 审、通过——会把「系统真的对了」这件事，悄悄偷换成「你以为它对了」。Review 亮了绿灯，却没有任何一个独立视角重建过意图。出路不是更强的单模型，而是**异质多模型审查 + 人站在 loop 之上（on the loop）抽样深审**。下面拆开讲。

## 一、把默认动作变成一个问题

先给个干净定义。**AI 结对时代的 code review**,指的是:当 AI agent 写下大部分代码后,人类审查的重心从「检查作者的机械正确性」转向「重建作者缺失的意图 + 守住架构、安全和系统知识」,同时把机械层审查(格式、lint、常见 bug)外包给专门的 AI 审查 agent。

Simon Willison 把这件事说得更狠。他引用 Strong DM 的两条原则——「代码不得由人编写 / 代码不得由人审查」——然后追问一句:当一半代码是 agent 写的,你到底在 review 什么?他给这种状态起了个名字,叫 **"cognitive debt"(认知负债)**:你**拥有**一堆既不是你写的、也没有任何人真正理解的代码([Simon Willison](https://x.com/simonw/status/2020161285376082326))。

认知负债不会立刻爆。它爆在三个月后——某个没人重建过意图的模块出了故障,而当初「审过」它的,只是另一个 AI。

## 二、命名这个陷阱:borrowed confidence

这一节是全文的题眼,术语得立住。

闭环自审最贵的失败模式,**不是漏掉一个 bug**。漏 bug 至少还有下一道防线。最贵的失败模式是 Addy Osmani 命名的 **"borrowed confidence"(借来的信心)**:AI 生成代码、另一个 AI 审查并批准,整个链条看起来一切正常、全程绿灯,于是「系统是确定对的」这个判断,被无声地替换成「**你觉得**它是对的」——而这份信心,是从一台机器那里借来的,没有任何人真的验过账([Addy Osmani, Agentic Code Review](https://addyosmani.com/blog/agentic-code-review/))。

它最隐蔽,恰恰因为它看起来最正常。漏 bug 会报错,borrowed confidence 不会——它交付的是一种平滑的、绿色的、无人负责的确定感。

而且同源模型的盲点是**相关**的。Osmani 引用一项研究:4 个 AI 审查工具并跑,**93.4% 的 bug 只被其中一个工具抓到**(⚠️ 此为 Osmani 转引,原研究链接待回溯,以转引口径引用)。换句话说,如果你只用一个工具、或者用一堆同源同架构的工具,你以为在做「多重审查」,实际上它们大概率在同一个地方一起瞎。Greptile 把这个叫二阶效应:第一层问题(能不能抓真 bug)基本解决了,**AI 审 AI 的相关盲点才是真正的战场**([Greptile](https://www.greptile.com/blog/ai-code-reviews-conflict))。

## 三、为什么自审偏差是必然的(机制层)

现象层的东西,第三方调研都能给你。这一节给的是别人给不了的:**为什么**异质审查有效、**为什么**自审必然偏。

第一个机制叫**自评估偏差(self-evaluation bias)**。让一个 agent 评价自己的产出,它会**过度自信地批准自己的平庸输出**——因为「生成」和「评判」共享同一套先验:那些它在生成时没想到的失败模式,它在评判时同样想不到。盲区是同一个盲区。这正是 borrowed confidence 的机制解释:自审不是偏见问题,是**信息结构**问题——评判者和生成者是同一个信息源,再自信也照不亮自己的背面。

第二个机制解释了异质审查**为什么**能救:因为它靠的**不是投票多数,而是三轴互补**。把同一段输出交给不同厂商、不同强项的模型审——一个偏**精度**(少误报)、一个偏**召回**(多抓真问题)、一个偏**genericness**(揪出放之四海皆可的空话)。三条轴各照亮一个面,合起来才逼近全貌。这跟「找三个一样的模型投票」是两回事:三个同源模型投出来的,只是同一个盲点被投了三次。

这就是为什么「4 工具、93.4% bug 只被一个抓到」在机制上是**必然**而非意外:每个工具是一条轴,轴与轴之间本就该只有少量重叠——重叠少不是 bug,是异质性在起作用的证据。异质审查的价值,恰恰藏在那些「只被一个工具抓到」的 bug 里。

## 四、处方:怎么配一套抗盲点的 review

把上面的机制翻译成可执行的结构,三件套:

**1. 异质多模型并跑。** 不同厂商、不同强项的审查器同时跑同一个 PR,覆盖精度/召回/genericness 三轴。关键是「异质」——两个不同来源的工具,胜过一个「最强」的单一工具。

**2. 一个 coordinator 去重定级。** 多个 reviewer 会产生重叠和噪声,需要一层协调把发现去重、按严重度排序、给出高信号总览。Cloudflare 在生产里最多跑 **7 个专门 reviewer**(安全 / 性能 / 质量 / 文档 / 发布 / 合规 / 内部 Codex),前面挂一个 coordinator 做去重定级([Cloudflare](https://blog.cloudflare.com/ai-code-review/))。你不需要 7 个,但你需要那个 coordinator 层——否则异质审查会淹死在自己的噪声里。

**3. 人站在 loop 之上(on the loop),不是里面(in the loop)。** 这是 Osmani 那句话的落地:人不再逐行读(in the loop),也不能全交给 AI 自审(off the loop),而是**站在 loop 之上抽样深审**——抽查意图重建、架构决策、安全暴露这些机器补不上的判断。机械层(格式、lint、常见 bug、安全模式)全外包,人一眼都不看;判断层(架构、公共 API 人体工学、算法选型、依赖安全、业务逻辑、可测性)人保留,采样式深挖。

> 一句话记法:**机械审查全交给机器,意图审查绝不外包。**

## 五、落地清单:非资深 builder 今天就能配的最小版

如果你是**独立 builder 或内容创作者**——能用 Claude Code / Cursor / API、能跑通脚本,但不是 systems engineer——你不需要 Cloudflare 那套 7-reviewer 编排。今天能配的最小抗盲点栈是这样:

1. **两家不同厂商的审查工具并跑。** 不是一个,不是同源的一堆——是**两家不同来源**。这一步就已经在对抗相关盲点了,配置成本几乎为零。
2. **审查前移成 push 前闸门。** 把 `/review` 挂在 push 之前,而不是等到 PR 阶段。push 前是抓 bug 最便宜的点——越晚发现越贵([Cursor BugBot](https://cursor.com/bugbot))。
3. **一次人工抽样,拒绝来源偏见。** 每批改动里抽一部分,自己动手重建一遍意图。审的时候**别问「这代码是资深工程师写的还是 agent 写的」,只问「它能跑吗、它安全吗」**——代码是一次性的,系统知识才是永久的([Daniela Petruzalek](https://danicat.dev/posts/20260303-code-reviews-in-2026/))。
4. **高风险变更强制 linear walkthrough。** 碰到 auth、支付、数据迁移这类改动,别抽样——逐行追一遍逻辑,把 cognitive debt 挡在门外。

这套东西的成本,比追一个「最强单模型」低得多,抗盲点能力却高得多。因为**review 的价值从来不在抓机械 bug**——那个交给机器最省——**它的价值在于:强制至少一个独立视角(一个人,或一个真正异构的模型)重新理解了这次改动。**

写代码变便宜了。理解,还没有。护城河就在这条没变便宜的缝里。
