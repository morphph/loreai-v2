LoreAI v2 — Pipeline Architecture

Organized by data flow · Updated 2026-04-08 · ● = human approval required

1
Data Collection
Raw material — everything starts here
Collect 0 0 * * 1-5 Mon–Fri 12:00am
collect-news.ts
7 tiers of sources collected in parallel: RSS (T0), Official Blogs (T1), Twitter/X — 36 accounts + 18 queries (T2), GitHub Trending + Releases (T3), HuggingFace (T3c), Hacker News (T4), Reddit (T5). Staleness filters per tier (7d RSS, 14d OpenAI, 60d HF). Dedup by URL.
news_items ~100–200 items/day → feeds Newsletter, Entity Extract, Freshness
2
Content Distribution
Downstream readers — newsletter subscribers, weekly digest
Newsletter 0 2 * * 1-5 Mon–Fri 2:00am
write-newsletter.ts
7-stage: Query 72h items → pre-filter (caps per source) → 3-tier agent filter (pick 18-25 best) → outline (Opus) → EN writer (Opus) → ZH writer (Opus, independent) → email via Buttondown.
content newsletters/{en,zh}/*.md filtered-items/*.json
Weekly Digest 0 5 * * 0 Sun 5:00am
write-weekly.ts
Aggregates Mon–Fri newsletters + filtered-items. Ranks by frequency + engagement + agent_score. Top 5 → Opus writes 200-400 word analysis. "5 Things That Mattered in AI This Week"
newsletters/weekly/{en,zh}/*.md
3
Knowledge Graph
Building the topic taxonomy — entities from news + flagship subtopics from research
Entity Extract 0 4 * * 1-5 Mon–Fri 4:00am
extract-entities.ts
Claude Sonnet extracts companies, models, tech concepts from all items (30h window). D2 guard: skips flagship subtopics — those are managed by Flagship Discovery.
topic_clusters (non-flagship entities only)
Flagship Discovery 30 7 * * 6 Sat 7:30am HUMAN APPROVAL
flagship-discovery.ts
Weekly full discovery — synthesizes official docs (Exa) + competitor content (Serper) into subtopic-pack.

Blocked: Writes draft pack to data/flagship-packs/. Pipeline pauses until human runs --approve to materializePack() → upserts subtopics + seeds keywords. No downstream content is generated for new subtopics without approval.
topic_clusters (flagship subtopics) keywords flagship-packs/*.json
topic_clusters feeds → SEO/AEO Engine
4
SEO / AEO Engine
Topical authority expansion + programmatic content generation at scale
Two inputs feed the queue: Freshness routes daily breaking news to existing subtopics (reactive, daily). Discovery expands keyword coverage systematically via B1→B2→B3 (proactive, Tue+Sat). Both write to create_queue which Generate consumes.
Flagship Freshness 30 4 * * 1-5 Mon–Fri 4:30am
flagship-freshness.ts
Reactive: Routes daily news signals to approved flagship subtopics. Sonnet classifies relevance. Triple dedup: vs queue, vs recent content, vs same-run.
→ create_queue (source=flagship_freshness)
Discovery Cycle 0 8 * * 2,6 Tue+Sat 8:00am
discovery-cycle.ts (C1→B1→B2→B3)
Proactive: C1: Subtopic discovery (prefers flagship packs) → B1: Expand keywords (Serper PAA + autocomplete) → B2: Intent grouping (Sonnet 4.6) → B3: Priority scoring (flagship-only guard) → queue jobs.
keywords keyword_groups → create_queue
create_queue → Generate
Generate — Programmatic SEO/AEO 0 6 * * 1-5 Mon–Fri 6:00am
process-queue.ts (B4)
Reads top-N jobs from create_queue by priority. For each: research (Serper + Exa, or Gemini Deep Research) → Claude Opus writes EN + ZH → validate links → write files + DB upsert → git push → Vercel deploy.

Content types: blog (1800-5000w), faq (800-1500w), compare (4000-5000w), glossary (200-500w), topic-hub (3000-5000w), deep-dive/cornerstone (5000-8000w).
Models: Opus for all types except FAQ/Glossary (Sonnet 4.6). Two research pipelines: Standard (Serper+Exa) or Gemini Deep Research.
content blog/*.md faq/*.md glossary/*.md compare/*.md topics/*.md → Vercel auto-deploy → live SEO/AEO pages
5
Feedback Loop
Measure → optimize → re-generate — closing the authority loop
Performance Cycle 0 10 * * 6 Sat 10:00am
performance-cycle.ts
Import GSC data (28d) → segment by position/CTR → detect anomalies (drops, low CTR) → queue underperforming pages for refresh. Closes the loop: live pages → GSC feedback → refresh → better pages.
snapshots → create_queue (type=refresh) → back to Generate
Health Report 0 3 * * 6 UTC Sat 11:00am SGT
/pipeline-health · loreai.dev/dashboard
Dashboard Health Report: overall score, 6 pipeline stages, content output, queue status, coverage gaps, live site checks, infrastructure, action items. Scheduled runs send Telegram summary.
snapshots (pipeline_health.*)
Orchestration: All steps run through daily-pipeline.sh — flock locking (no concurrent runs), auto git pull, validation after Collect/Newsletter, auto git commit+push (Vercel deploy), email send after Newsletter.
Key insight: Three sources feed create_queue — Freshness (reactive, daily news), Discovery (proactive, keyword expansion), Performance (feedback, refresh). Generate consumes them all. This is the programmatic SEO/AEO engine.
