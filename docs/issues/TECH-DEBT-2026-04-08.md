## 3. Queue Strategy (Current)

### Scoring formula
```
score = volume × (1/competition_divisor) × intent_multiplier + timeliness_bonus
final_score = score × cluster_diversity_multiplier
```

### Scoring parameters (`scripts/lib/priority.ts`)

| Factor | Values |
|--------|--------|
| Volume | max(search_volume) in group; fallback = keyword_count × 8 |
| Competition | low: ÷0.2 (5× boost), medium: ÷0.5, high: ÷1.0, very_high: ÷2.0 |
| Intent | commercial: 3×, informational: 1.5×, definitional: 1×, navigational: 0.5× |
| Timeliness | +5000 if keyword matches news ≤48h; linear decay to 0 at 168h |
| Cluster diversity | Rank 1-5: 1.0×, 6-10: 0.7×, 11-20: 0.4×, 21+: 0.2× |

### Junk filtering
170+ regex patterns in `priority.ts` — catches hashtags, doc headers, marketing CTAs, ancient-manuscript "codex", competitor nav keywords, non-English terms. Plus off-topic check for 25+ polluted clusters.

### Queue consumption
- `process-queue.ts` runs daily at 6:00am SGT
- Picks top 5 jobs by `priority_score DESC`
- Generates EN + ZH content for each
- Status flow: `pending` → `completed` (or stays `pending` on failure)

### Key observations

**7 successful runs out of 8 in the last 2 weeks** (weekdays only, no runs Sat/Sun or Apr 4-5 weekend).

**But zero queue drafts since Apr 3.** The pipeline detects signals and routes them, but isn't creating new queue items. Breakdown:
- **28 total queue drafts created** across all runs (Mar 27 - Apr 3)
- **All 31 were immediately cancelled** (status=cancelled in DB)
- **0 freshness-sourced content has ever been generated**

### Recurring errors
1. **JSON parse failures** — Claude returns markdown-wrapped JSON (`` ```json ... ``` ``) instead of raw JSON. The flagship filter and Codex routing both hit this. Currently handled via `fail-open` (skip filter, process all signals) but the routing step crashes on retry exhaustion.
2. **ETIMEDOUT** — Claude CLI spawn timeout during routing. Intermittent, hits ~1 in 4 runs.
3. **Git push failures** — VPS had dirty git state preventing auto-push (now fixed).

### Why all freshness queue items get cancelled
The freshness pipeline creates `create_queue` items with `source='flagship_freshness'`, but all 31 items have `status='cancelled'`. This needs investigation — likely the freshness items are being deduplicated against existing discovery-sourced queue items, or there's a downstream cancellation step.
