3. Simon Willison Demonstrates Web-Fetch Data Exfiltration Against Claude

The story every AI builder should read today. Simon Willison shows how a crafted prompt can trick Claude into using its web-fetch tool to exfiltrate sensitive user data to an attacker-controlled URL. The attack doesn't exploit a model weakness — it exploits the permissions you gave the model. If your Claude integration has both access to sensitive data and the ability to make outbound web requests, you have an exfiltration vector. The fix isn't better guardrails; it's smaller permission surfaces. →

🎓 MODEL LITERACY

Tool-Use Attack Surface: Today's exfiltration attack from Willison exploits web-fetch permissions, not the model itself. As AI agents gain more tools — file access, code execution, web browsing, database queries — the attack surface becomes the union of all tool capabilities. The critical question isn't "can the model be tricked?" (it can) but "which tools can both read sensitive data AND reach the network?" A tool that reads your codebase is fine. A tool that fetches URLs is fine. An agent with both is an exfiltration vector. Understanding which tool combinations create dangerous capability surfaces is the new security audit — and most builders haven't done it yet.

🎯 PICK OF THE DAY

Willison's exfiltration demo proves the AI security perimeter has already shifted — and most builders are defending the wrong layer. Simon Willison didn't find a bug in Claude. He found a bug in how we deploy Claude. The web-fetch exfiltration attack works because tool permissions are configured additively — each tool seems safe in isolation, but the combination of "can read user data" and "can make outbound HTTP requests" creates a side channel that no amount of model alignment will close. This is the same class of vulnerability that plagued early web apps (SSRF, open redirects) — we solved it there with least-privilege access and network segmentation, not by making the application smarter. The fix for AI tools is the same: smaller permission surfaces, not better guardrails. Audit which of your agent's tools can read sensitive data. Audit which can reach the network.
