# Claude 拿起了画笔：Anthropic Labs 推出 Claude Design

## 🧠 发布动态

### Claude 拿起了画笔：Anthropic Labs 推出 Claude Design。
这不是在 Figma 里加个 AI 助手 — **Claude Design** 让你用对话直接生成原型、幻灯片和单页设计稿。Anthropic 的逻辑很清晰：下一代设计工具的起点不是画布，而是对话。对产品经理和独立开发者来说，从想法到可视化原型的路径被压缩到了几句话。现在就在 claude.ai 上试。 [详情 →](https://www.anthropic.com/news/claude-design-anthropic-labs)

### Auto Mode 上线 Claude Code：布置任务，转身走人。
**Claude Code** 的 Auto Mode 面向 Max 用户开放 — 取消所有权限弹窗，给它一个任务，回来收结果。这是很多开发者等了很久的"零摩擦自主编码"体验。风险自担，但生产力释放是实打实的。 [详情 →](https://www.claude.com/blog/auto-mode)

### Claude 登陆 Amazon Bedrock 全面开放，覆盖 27 个 AWS 区域。
**Opus 4.7** 和 **Haiku 4.5** 现在可以在 Bedrock 上自助开通，用标准 Messages API 调用，不需要跟 Anthropic 谈合同。AWS 上的企业团队可以直接在控制台接入，门槛降到了最低。 [详情 →](https://platform.claude.com/docs/en/build-with-claude/claude-in-amazon-bedrock)

## 🔧 开发者工具

### GitHub 官方 MCP Server 发布 1.0 — AI Agent 获得完整 GitHub 访问权限。
用 Go 写的，支持 repo、issue、PR、Actions 全套操作。任何兼容 MCP 的 AI Agent 现在都能直接跟全球最大代码托管平台对话。这是 AI 编码 Agent 和真实开发工作流之间缺失的那座桥。（373 likes | 39 RTs）[详情 →](https://x.com/rseroter/status/2045254911685017961)

延伸阅读：如果你还不熟悉 MCP Server 的接入方式，可以看看我们之前的指南 — [如何集成 MCP Server](https://loreai.dev/blog/how-to-integrate-a-mcp-server)。

**Anthropic 推出 `ant` CLI**：第一方命令行工具，支持原生 Claude Code 集成和 YAML 资源版本管理。开发者可以把 prompt 配置和代码一起做版本控制，API 交互也能脚本化了。 [详情 →](https://platform.claude.com/docs/en/api/sdks/cli)

**Advisor Tool 进入公测**：在生成过程中把快速执行模型和更聪明的顾问模型配对使用 — 用执行模型的 token 价格拿到接近 Opus 的质量。对跑长时间 Agent 任务的团队来说，这是等了很久的成本/质量平衡点。添加 `advisor-tool-2026-03` beta header 即可启用。 [详情 →](https://platform.claude.com/docs/en/agents-and-tools/tool-use/advisor-tool)

**Compliance API 上线**：企业安全和合规团队现在可以用 API 审计所有 Claude 平台活动。对受监管行业来说这是准入门槛级功能 — 没有审计能力，很多企业根本不敢用。 [详情 →](https://www.claude.com/blog/claude-platform-compliance-api)

## 📝 技术实战

### Anthropic 官方定义了五种多智能体协作模式。
从简单的委托到复杂的竞争式验证，每种模式都给了清晰的适用场景。这是 Agent 构建社区一直缺的那份参考架构文档 — 别再自己瞎摸索了，先看看官方怎么分类的。 [详情 →](https://www.claude.com/blog/multi-agent-coordination-patterns)

**Claude Code 百万上下文会话管理指南**：官方教你怎么用好 100 万 token 上下文窗口 — 包括压缩策略和会话卫生习惯。跑多小时编码会话的开发者必读，不然上下文一满效率直接崩。 [详情 →](https://www.claude.com/blog/using-claude-code-session-management-and-1m-context)

**Claude Code 工具系统设计哲学**：Anthropic 工程师解释了 Agent 如何感知和操作代码库 — 不是"给 AI 加工具"这么简单，而是重新思考工具对 Agent 意味着什么。自己做 Agent 工具链的，这篇必看。 [详情 →](https://www.claude.com/blog/seeing-like-an-agent)

**Claude Code 子 Agent 使用指南**：什么时候拆子 Agent、怎么划定它的工作范围、怎么避免上下文污染。直接可用于今天的 Claude Code 工作流。 [详情 →](https://www.claude.com/blog/subagents-in-claude-code)

**Simon Willison 逐行对比 Opus 4.6 和 4.7 的系统提示词**：改了什么安全护栏、推理指令、工具调用模式 — 一目了然。理解这些变化能帮你写出"顺着模型思路走"的 prompt，而不是跟它较劲。（Simon Willison 是 Django 联合创始人，prompt 工程领域的标杆人物。） [详情 →](https://simonwillison.net/2026/Apr/18/opus-system-prompt/#atom-everything)

## 🎓 模型小课堂

**模型级联（Advisor 模式）**：想象你有两个助手 — 一个手脚快但偶尔犯错，一个更聪明但慢且贵。模型级联就是让快的那个干活，遇到拿不准的关键决策时自动请教慢的那个。Anthropic 新上线的 Advisor Tool 就是这个模式的产品化：用 Haiku 级别的成本跑大部分任务，只在需要时调用 Opus 级别的判断力。随着 Agent 工作负载越来越长、越来越贵，"什么时候该路由到哪个模型层级"正在成为基础设施层面的核心决策。

## 🎯 今日精选

**Claude Design 不是 Figma 的竞争对手 — 它重新定义了"设计工具"的含义**：Anthropic Labs 推出 Claude Design，很多人的第一反应是"又一个 AI 设计工具"。但仔细看就会发现，这不是在画布上加 AI 辅助，而是从对话出发生成视觉产出 — 原型、幻灯片、文档，用说的就行。这背后的赌注是：下一代创意工具的交互范式根本不需要画布。对独立开发者和小团队来说，这意味着从产品想法到可分享的视觉原型，可能只需要几分钟的对话。Claude 从代码、文本，到现在的设计 — Anthropic 正在一步步证明，AI 原生工作流不是在现有工具里加个 copilot，而是重新发明工具本身。 [详情 →](https://www.anthropic.com/news/claude-design-anthropic-labs)
